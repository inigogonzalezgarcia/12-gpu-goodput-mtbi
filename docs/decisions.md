# Design decisions

## 1. Simulate, then measure the simulation like a real cluster

The simulator writes the same event log a real cluster could produce (docs/event-log.md), and the analyzer only reads that log. The analyzer does not know anything the simulator knows, so the same code would measure a real job, and the tests can check the analyzer on hand-written logs where every number is known.

## 2. Account for every GPU-hour

Goodput alone says how much was wasted, not where. Splitting the waste into checkpoint writes, lost work, detection, waiting and restart shows which change helps: the baseline loses most to checkpoint writes, the no-spares fleet to waiting, the firmware regression to more frequent interruptions. Each improvement in the scenarios moves exactly one of these, and the tests check that it does.

## 3. Charge waste to the interruption that caused it

A cause that happens often but is detected in seconds can cost less than a rare one that hangs for 30 minutes. Ranking causes by GPU-hours, not by count, is what makes "fix hang detection" or "fix this firmware" a decision with a number on it.

## 4. Formulas and simulation side by side

Young/Daly and the first-order goodput model give the answer instantly; the simulation shows how far reality (waiting for spares, randomness) moves it. The tests check the two agree within 2.5 points, and that Daly's interval is as good as the best interval found by brute force.

## 5. Ranges, not single numbers

A 28-day run with about 45 interruptions is noisy. Every scenario runs 20 seeds and reports p10–p90. The same seeds are used for every scenario (common random numbers), so differences between scenarios are mostly the effect of the change.

## 6. Results are checked into the repo and verified by CI

docs/results.md is generated by `goodput report`, and CI fails if the committed file no longer matches what the code produces. Numbers quoted in the README cannot silently drift from the code.

## 7. Standard library only

Python 3.11+, no dependencies. `python -m unittest` runs without installing anything, and the HTML report is one file with inline SVG charts.
